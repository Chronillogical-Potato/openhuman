# Issue 6964 implementation ledger

Worktree: `issue-6964-file-intake`. Root base: `a4fb192360`.

## Requirements

- Preserve arbitrary original uploads in the permitted acting workspace, across restart.
- Prefer native multimodal input when both selected-model facts and the actual transport support the modality, MIME and source. Keep preprocessing faithful and provider payloads ephemeral.
- Persist ordered typed media references, preserving captions and frozen session prompts/tools.
- Fall back to bounded image readouts, text/document extraction, archive listings, or metadata with accessible paths. Never automatically extract archives, transcribe audio or analyze full videos.
- Support explicit `image_paths` for named/collapsed delegation and legacy markers; reject vision tasks without a resolvable image before inference.
- Preserve credential/path security floors and untrusted-channel attachment gates.
- Implement library behavior in its owning repository. Publish dependency PRs before root gitlinks. Keep every commit, with no squash.

## Implementation

1. TinyAgents: generic arbitrary upload resolution; bounded ZIP/TAR/TAR.GZ listing with pre-allocation ZIP admission; lossless PNG derivatives; durable audio/video/document transcript references; model catalog modality facts.
2. TinyInference: conservative modality/MIME/source transport contract, provider serializers, discovery/cache modality facts and wrapper forwarding.
3. TinyDocs: bounded PDF/Office extraction and selective PDF rendering, shared bus types and held outputs. Parser internal allocations remain outside a blanket bound; caller timeouts do not stop blocking parser work.
4. OpenHuman: workspace storage before persistence, typed bridges, contextual enrichment preserving media, provider routing and derivative caches, named/collapsed vision delegation, direct session and CLI/channel integration.
5. Frontend: arbitrary picker/drop/paste uploads, reversible transport compression and original video bytes. Removed the primary-model vision upload gate. Normal sends reuse the durable content returned by the core append boundary; restored uploads display filename chips.
6. Persistence and queue integration: core append stages user uploads and strips legacy byte/poster/preview metadata. Queue previews preserve original display names and match staged/raw messages; immediate queued sends preserve existing ordering, with possible duplicate originals during later history append.
