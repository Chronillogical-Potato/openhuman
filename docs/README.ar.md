# التثبيت

حمّل مثبتات التطبيق من [tinyhumans.ai/openhuman](https://tinyhumans.ai/openhuman?utm_source=github&utm_medium=readme) أو من صفحة [إصدارات GitHub](https://github.com/tinyhumansai/openhuman/releases/latest).

للتثبيت عبر سطر الأوامر (Homebrew و Debian/Ubuntu `.deb` و AUR ونصوص التثبيت وملاحظات المنصات)، راجع **[INSTALL.md](../INSTALL.md)**.

## تثبيت تطبيق سطح المكتب

- **macOS** (Apple Silicon و Intel): نزّل ملف `.dmg` أو ثبّته عبر Homebrew:
  ```bash
  brew install --cask openhuman
  ```
- **Windows**: نزّل المثبت أو ثبّته عبر winget:
  ```powershell
  winget install TinyHumans.OpenHuman
  ```
- **Linux**: حمّل حزمة `.deb` أو ملف `.AppImage`، أو ثبّت عبر AUR (`openhuman-bin`).

## التثبيت كأداة سطر أوامر / خادم مستقل (Headless)

إذا كنت تبني وكيلاً يعمل على خادم بدون واجهة رسومية، ثبّت النواة مباشرة:

```bash
cargo install --git https://github.com/tinyhumansai/openhuman openhuman
```

أو شغّلها عبر حاوية Docker:

```bash
docker run -d -p 8080:8080 -v ~/.openhuman:/root/.openhuman tinyhumansai/openhuman:latest
```

# الميزات الرئيسية

## نواة Rust فائقة السرعة

النواة مبنية بالكامل بلغة Rust مع استهلاك منخفض جداً للذاكرة وسرعة استجابة فائقة. تضمن لك إدارة الموارد بكفاءة، وأمان خيوط المعالجة، والعمل دون أي اعتماديات ثقيلة.

## ذاكرة دائمة واسترجاع ذكي

> يقوم OpenHuman بفهرسة المستندات والمحادثات والمعارف المكتسبة في محرك الذاكرة، ويجيب على الأسئلة مع ذكر المصادر والاقتباسات بدقة.

يتجاوز OpenHuman مرحلة الانتظار أو الإعداد المطول. أضف مصادرك (مجلدات، ملفات، روابط، مستودعات GitHub، موجزات RSS، وتطبيقات متصلة)، ثم اضبط جدول المزامنة، وسيجيب الوكيل بالاعتماد على [الذاكرة](../gitbooks/features/memory.md) مباشرة.

بمزامنة واحدة، يمتلك الوكيل سياقاً كاملاً وموجزاً لبريدك الوارد، وتقويمك، ومستودعاتك، ومستنداتك، ورسائلك. لا حاجة لأسابيع من التدريب، إنه يعمل تحت سيطرتك التامة وفوراً.

## منسق عمليات متكامل وليس مجرد روبوت محادثة

معظم أطر عمل الوكلاء تدير وكيلاً واحداً في حلقة تكرارية بسيطة. بينما OpenHuman هو **[منسق عمليات (Orchestrator)](https://tinyhumans.gitbook.io/openhuman/features/orchestration)** متكامل:

<p align="center">
 <img src="../gitbooks/.gitbook/assets/orchestration.png" alt="مخطط التنسيق في OpenHuman">
</p>

> الرسائل بين الوكلاء مشفرة طرفاً لطرف عبر بروتوكول Signal، ما يتيح لك ربط أي أداة (Claude Code و Codex و OpenClaw و Hermes) وتنسيق جميع وكلائك وأدواتك بسلاسة وأمان.

- **رسم بياني بدلاً من الحلقات**: تعمل كل جولة محادثة كرسم بياني مع نقاط حفظ وتفتيش عبر [tinyagents](https://github.com/tinyhumansai/tinyagents)، يمكن إيقافها مؤقتاً لطلب موافقة بشرية، وتستمر بعد إعادة تشغيل النظام، وتستأنف من منتصف التنفيذ.
- **أسطول من الوكلاء الفرعيين المتخصصين**: يمكن للوكلاء التفريع حتى ثلاثة مستويات؛ والوكيل الذي يتعثر يتحول إلى تقرير للأسباب الجذرية.
- **تواصل مشفر طرفاً لطرف بين الوكلاء**: تتواصل النسخ وتنسق المهام فيما بينها عبر جلسات E2E ببروتوكول Signal، مع دعم مدفوعات x402. لا يمكن لأي خادم وسيط قراءة النصوص الصريحة.

## مسارات عمل مرئية (Workflows)

مستوحاة من n8n و Zapier، تنقل [مسارات العمل](https://tinyhumans.gitbook.io/openhuman/features/workflows) الأتمتة المرئية القائمة على المحفزات إلى وكلائك. والفرق الجوهري: الوكلاء هم من يبنونها لك. اطلب من الوكيل أتمتة معينة، وسيقترح عليك رسماً بيانياً عبر [tinyflows](https://github.com/tinyhumansai/tinyflows) يمكنك مراجعته وتعديله على لوحة مرئية قبل الحفظ.

<p align="center">
 <img src="../gitbooks/.gitbook/assets/workflows.png" alt="لوحة مسارات عمل OpenHuman">
</p>

> يقترح الوكيل مسار العمل؛ وتراجعه وتعتمد حفظه على اللوحة التفاعلية.

مسارات العمل المحفوظة دائمة وتعمل بالمحفزات: تُطلق بمهام Cron المجدولة، أو الـ Webhooks، أو أحداث القنوات، وتستمر عبر عمليات إعادة التشغيل، وتضع الإجراءات المؤثرة خلف بوابات موافقة صريحة.

## التضمين في تطبيقات Rust

يمكنك تضمين نواة OpenHuman كمكتبة في تطبيقات Rust الخاصة بك:

</div>

<div dir="ltr">

```rust
use openhuman::{Access, AgentSpec, McpServer, Provider, Runtime};

let runtime = Runtime::builder()
    .local_cortex("./cortex.db")
    .spawn()
    .await?;

let reviewer = runtime.agent(
    AgentSpec::new("reviewer")
        .system_prompt("You review pull requests and never edit files.")
        .access(Access::readonly())
        .skills_dir("./skills/review")        // copied into this agent's own skills root
        .action_dir("/srv/checkouts/pr-42"),
)?;

let fixer = runtime.agent(
    AgentSpec::new("fixer")
        .provider(Provider::openai_compatible("https://api.example/v1", "sk-…").model("gpt-5"))
        .access(Access::full())
        .mcp(McpServer::stdio("github", "gh-mcp", ["stdio"]))
        .action_dir("/srv/checkouts/pr-42"),
)?;

let review = reviewer.run("Summarise the risks in this change.").await?;
let fix = fixer
    .turn(format!("Address these findings:\n{}", review.reply))
    .send()
    .await?;
println!("{}", fix.reply);

// Continue a conversation with the same agent.
let again = fixer.turn("Now run the tests.").session(&fix.session_id).send().await?;
println!("{}", again.reply);
```

</div>

## مفتاح TinyHumans API موحد لكل شيء

يغطي مفتاح TinyHumans API الواحد استنتاج نماذج LLM المدارة (بما في ذلك الوصول إلى دليل نماذج OpenRouter)، والبحث على الويب، والتضمينات الشعاعية، وتوليد الوسائط، والتكاملات، والصوت، وترتيب Jev. مرره مرة واحدة برمجياً (`.api_key("th_...")`) أو كمتغير بيئة `OPENHUMAN_BACKEND_API_KEY`، وستعمل جميع هذه الخدمات فوراً. التفاصيل: [مفتاح TinyHumans API](../gitbooks/developing/tinyhumans-api-key.md).

## المساهمة البرمجية من المصدر

مساهم جديد؟ ابدأ بـ [`CONTRIBUTING.md`](../CONTRIBUTING.md) للتعرف على مسار عمل التفريع (Fork) وطلبات الدمج (PR) وأوامر التحقق المحلية، أو استخدم موجه وكيل الذكاء الاصطناعي الجاهز في [`CONTRIBUTING-BEGINNERS.md`](./CONTRIBUTING-BEGINNERS.md#optional--let-an-ai-coding-agent-guide-you). الخطوات المختصرة:

1. ثبّت Git و Node.js 24+ و pnpm 10.10.0 و Rust 1.96.1 (`rustfmt` + `clippy`) و CMake و Ninja و ripgrep والمتطلبات الأساسية لبناء سطح المكتب لمنصتك.
2. قم بعمل Fork واستنسخ المستودع، ثم شغّل `git submodule update --init --recursive` قبل `pnpm install` حتى يتم حل اعتماديات Rust الداخلية ضمن `vendor/` (مثل tinyagents و tinyflows و tinychannels و tinymemory وغيرها).
3. استخدم `pnpm dev` للعمل على واجهة الويب فقط، أو `pnpm --filter openhuman-app dev:app` (على macOS) أو `pnpm dev:app:win` (على Windows) لغلاف سطح المكتب، ونفّذ عمليات الفحص الموجهة مثل `pnpm typecheck` و `pnpm format:check` و `cargo check -p openhuman --lib` قبل إنشاء طلب الدمج (PR).

تنقسم مساحة عمل Rust تحت `crates/` إلى `crates/openhuman-core` (الحزمة `openhuman`: النواة وأداة سطر الأوامر `openhuman-core`)، و `crates/openhuman-app` (غلاف سطح المكتب المبني بـ Tauri)، و `crates/openhuman-embed` (واجهة المكتبة للتضمين)، و `crates/openhuman-rpc` (عقود RPC المشتركة والعميل)، و `crates/openhuman-tui` (عميل الطرفية). راجع [بناء نواة Rust](../gitbooks/developing/building-rust-core.md) و [AGENTS.md](../AGENTS.md#repository-map) للاطلاع على الهيكل الكامل.
